# Робота з сесіями в OpenCode

*Read this in other languages: [English (sessions.md)](sessions.md)*

OpenCode автоматично зберігає ваші розмови в **сесіях** — окремих історіях чату, які зберігаються в SQLite базі даних `~/.opencode/db.sqlite`. Розуміння того, як ефективно використовувати сесії, є ключем до найкращих результатів від вашого ШІ-помічника.

## Що таке контекстне вікно?

Кожна ШІ-модель має **контекстне вікно** — максимальний обсяг тексту (в **токенах**), який модель може "бачити" одночасно. Це як короткочасна пам'ять моделі:

- **Малі моделі** (напр. `deepseek-v4-flash-free`): ~32K–128K токенів
- **Великі моделі** (напр. Claude, GPT-4): ~200K токенів

Кожне ваше повідомлення і кожна відповідь ШІ споживають частину цього вікна. Зі зростанням розмови старіші повідомлення виштовхуються з видимого контексту.

## Чому свіжі сесії важливі

Коли сесія заповнюється:

| Проблема | Наслідок |
| :--- | :--- |
| **Насичення контексту** | Модель "забуває" ранні інструкції або деталі |
| **Погіршення якості** | Відповіді стають розмитими, менш точними |
| **Галюцинації** | Модель починає вигадувати замість згадувати |
| **Повільна робота** | Довші запити = повільніші відповіді та вища вартість |

**Нова сесія дає моделі "чистий аркуш"** — вона може повністю зосередитись на поточному завданні, не відволікаючись на непов'язану історію.

## Дії з сесіями

### Команди в TUI (в чаті)

| Дія | Команда / Скорочення | Опис |
| :--- | :--- | :--- |
| **Нова сесія** | `Ctrl+N` | Створити нову порожню сесію |
| **Перемикання сесій** | `Ctrl+A` | Відкрити перемикач сесій, навігація стрілками, `Enter` для вибору |
| **Список та відновлення** | `/sessions` | Показати всі сесії, вибрати для відновлення |
| **Відновити (alias)** | `/resume` | Те саме, що `/sessions` |
| **Продовжити (alias)** | `/continue` | Те саме, що `/sessions` |
| **Довідка** | `/help` | Показати всі доступні команди |

**Перемикання сесій інтерактивно:**

1. Натисніть `Ctrl+A` щоб відкрити перемикач сесій
2. Використовуйте `↑`/`↓` або `j`/`k` для навігації
3. Натисніть `Enter` щоб завантажити вибрану сесію

**Список та відновлення через команду:**

1. Введіть `/sessions` (або `/resume` чи `/continue`)
2. Перегляньте список останніх сесій
3. Виберіть одну для відновлення повного контексту

### CLI команди

| Команда | Опис |
| :--- | :--- |
| `opencode session list` | Показати всі сесії у вигляді таблиці |
| `opencode session list --format json` | Показати сесії у форматі JSON |
| `opencode session list -n 5` | Показати лише 5 останніх сесій |
| `opencode --continue` | Відновити останню сесію (скорочено: `opencode -c`) |
| `opencode --session ses_abc123` | Відновити конкретну сесію за її ID |

### Гарячі клавіші

| Клавіші | Дія |
| :--- | :--- |
| `Ctrl+N` | Створити нову сесію |
| `Ctrl+A` | Відкрити перемикач сесій |
| `Ctrl+X L` | Список всіх сесій |
| `Ctrl+C` | Вийти з OpenCode |
| `Esc` | Закрити діалог / скасувати |

## Стратегія: спочатку план, потім реалізація

Найефективніший спосіб роботи над складними завданнями — **розділити їх на окремі сесії**:

```text
Сесія 1: ПЛАНУВАННЯ
─────────────────────────────────────────────
  Модель: легка / дешева (напр. deepseek)
  Мета:   проаналізувати вимоги, створити
          детальний покроковий план
─────────────────────────────────────────────
         │
         │ Скопіювати план (або зберегти у файл)
         ▼
Сесія 2: РЕАЛІЗАЦІЯ
─────────────────────────────────────────────
  Модель: потужна (напр. Claude, GPT-4)
  Мета:   виконати план, написати код,
          запустити тести
─────────────────────────────────────────────
```

**Чому це працює:**

- Сесія планування залишається **легкою та швидкою** — немає потреби в потужній моделі
- Сесія реалізації починається з **чіткого, повного плану** в контексті
- Кожна сесія має **максимум простору** у своєму контекстному вікні для важливого
- Ви можете використовувати **різні моделі** для кожного етапу (дешеву для планування, потужну для коду)

> **Порада:** Зберігайте план як `.md` файл у вашому проекті. У сесії реалізації почніть з читання цього файлу через ШІ.

## Коли створювати нову сесію

Створюйте нову сесію коли:

- ✅ Починаєте **нову функцію** або **нове завдання**
- ✅ Перемикаєтесь між **непов'язаними проблемами**
- ✅ Поточна розмова відчувається **повільною або розфокусованою**
- ✅ Хочете **змінити модель ШІ** посеред роботи
- ✅ План готовий і час **реалізовувати**
- ✅ Потрібно **відлагодити** складну проблему без історії, що заважає

**Продовжуйте поточну сесію коли:**

- ✅ Ви все ще працюєте над **тим самим завданням**
- ✅ Контекст ще не перенасичений
- ✅ Потрібно щоб ШІ **пам'ятав** попередні деталі

## Поради та найкращі практики

1. **Називайте сесії змістовно** — OpenCode автоматично дає назви, але описові назви полегшують навігацію через `/sessions`.
2. **Використовуйте `--continue` для швидкого повернення** — `opencode -c` миттєво відновлює останню сесію.
3. **Форкайте коли сумніваєтесь** — Якщо не впевнені, чи варто починати нову сесію, все одно створіть. Завжди можна повернутись через `/sessions`.
4. **Плани переносяться** — План, написаний в одній сесії, працює в будь-якій іншій. Зберігайте його як файл, а не лише в історії чату.
5. **Модель під задачу** — Використовуйте швидкі/дешеві моделі для дослідження та планування; потужні моделі — для реалізації та налагодження.
