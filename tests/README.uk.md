# Автоматичне тестування в OpenCodeWizard

*Читати іншими мовами: [English (README.md)](README.md)*

Цей каталог містить тестовий фреймворк для перевірки працездатності скриптів автоматизації OpenCodeWizard у різних середовищах.

Тестування виконується автоматично за допомогою Docker-контейнерів, що дозволяє ізолювати встановлення системних пакетів та перевіряти поведінку скрипта без впливу на вашу основну операційну систему.

---

## Структура каталогу

- **`run_tests.sh`** — головний скрипт запуску тестів. Він керує створенням контейнерів, встановленням залежностей, запуском інсталятора в німому/неінтерактивному режимі та виконанням перевірок.
- **`verify_install.sh`** — перевірочний скрипт, який запускається всередині кожного контейнера. Він виконує перевірки (assertions) для підтвердження того, що WezTerm, OpenCode CLI та плагіни встановлені правильно, а конфігураційні файли є валідними та містять правильні параметри.
- **`README.md`** — англомовна версія цього посібника.
- **`README.uk.md`** — україномовна версія цього посібника (цей файл).

---

## Цільові середовища

Автоматичні тести виконуються в контейнерах таких дистрибутивів Linux:
1. **Ubuntu** (`ubuntu:latest`) — тестує інтеграцію `apt-get`, реєстрацію в `update-alternatives` та налаштування терміналу XDG.
2. **Fedora** (`fedora:latest`) — тестує інтеграцію `dnf`.
3. **Arch Linux** (`archlinux:latest`) — тестує інтеграцію `pacman`.
4. **PowerShell Core** (`mcr.microsoft.com/powershell:latest`) — перевіряє синтаксичну валідність Windows-скрипта `OpenCodeWizard.ps1` за допомогою AST-парсеру PowerShell.

## Як це працює

Тестування в Docker повністю автоматизовано і виконується без участі користувача завдяки німому (неінтерактивному) режиму:

1. Скрипт `run_tests.sh` перевіряє, чи запущено демон Docker.
2. Запускається контейнер із відповідним дистрибутивом Linux.
3. Всередині контейнера встановлюються мінімальні залежності ([Git](../docs/git.uk.md), `sudo`, `curl`, `nodejs`, `npm`).
4. Контейнер клонує репозиторій зі змонтованого локального каталогу (`git clone /src/OpenCodeWizard /app`).
5. Запускається `./OpenCodeWizard.sh --silent`. Скрипт встановлення виконується неінтерактивно, приймаючи всі значення за замовчуванням.
6. Викликається `./tests/verify_install.sh`, який перевіряє:
   - Присутність `wezterm` та `opencode` в PATH та їхні версії.
   - Існування конфігураційних файлів `wezterm.lua` та `opencode.jsonc`.
   - Правильність імені плагіна `"oh-my-opencode"` (перевіряє відсутність застарілого запису `"oh-my-openagent"`).
   - Наявність експорту змінних у `~/.bashrc`.
   - Створення ярлика запуску на робочому столі, його права на виконання та коректність команди запуску.

## Як запустити тести локально

Для запуску тестів вам знадобиться встановлений та запущений **Docker**.

1. Відкрийте термінал у кореневій папці проекту.
2. Виконайте команду для запуску:
   ```bash
   ./tests/run_tests.sh
   ```

Скрипт по черзі виконає всі перевірки та виведе підсумковий звіт. Якщо всі тести пройдено успішно, він завершиться з кодом `0`. У разі помилки в будь-якому контейнері — поверне ненульовий код помилки, що робить його придатним для використання в CI/CD (наприклад, GitHub Actions).

### Тестування поточного стану (Локальні зміни)
За замовчуванням скрипт копіює всі локальні зміни (включаючи незакомічені файли) для запуску тестів у вашій поточній робочій директорії:
```bash
./tests/run_tests.sh
```

### Тестування стану репозиторію на GitHub (Post-Push)
Щоб протестувати точний стан репозиторію, клонованого безпосередньо з GitHub (імітуючи поведінку після пушу), запустіть окремий скрипт тестування GitHub:
```bash
./tests/run_tests_github.sh
```
